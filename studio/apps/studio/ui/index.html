OdinGuard Studio

kein Profil

Ein Profil ist die einzige Quelle für ein Release: Module, Commands, Signaturen, Branding, Ports, Schlüsselpfade und Rollout-Stufe. Geheimnisse stehen nie im Profil, nur ihre Dateipfade.

Cheat-Signaturen nach Tool-Gruppe (Präfix der ID, z. B. OG-RCX-001 → RCX). „Standard“ nimmt die Aktion jeder einzelnen Signatur, „aus“ lässt die Gruppe weg, eine Aktion ersetzt sie für die ganze Gruppe. „Client“ = Einträge, die der Guard prüfen kann (der Rest sind Analysedaten). Eigene Signaturen: weitere TOML-Datei unter Profil → Signatur-Quellen.

GRF-Prüfung wie bei Gepard, aber patcher-tauglich: Jede GRF aus DATA.INI muss eine freigegebene Version (Größe + Tabellen-Hash, im Hintergrund zusätzlich der Datei-Hash) oder ein erlaubter Mod sein. Vor einem Patch: gepatchten Client einlesen mit „alte Versionen behalten“, Server-Konfig ausrollen, dann patchen. odin.grf und das Competitive-Pack trägt der Build selbst ein.
